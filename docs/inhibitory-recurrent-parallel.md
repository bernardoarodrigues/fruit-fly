# Exact parallel inhibitory intervals

The new [experimental module](../scripts/inhibitory_recurrent_parallel.py) passed **103/103 bounded synthetic checks** against the frozen serial kernel. The [receipt](../validation/inhibitory-recurrent-parallel-checks.json) retains all compared arrays, their structural metadata, and compiler diagnostics. This establishes agreement on the tested fixtures and actual four-thread execution. Full-graph parity and speed remain to be measured under a separately frozen plan. No production default, original kernel, scalar solver, graph, weight or input convention was changed.

The API is the same `FactorialNetwork(neuron_ids, indptr, targets, weights, arm, input_indices, selected_indices, seed=11)`, with unchanged `advance`, `step` and `checkpoint` schemas. A caller explicitly invokes `configure_threads(4)` before running the parallel module and records `parallel_runtime_info()`. Importing the module does not change thread settings. This thread mask is a Numba runtime setting, so callers must record it rather than infer it from the module name.

The module is an explicit copy of [the frozen serial implementation](../scripts/inhibitory_recurrent_kernel.py) with a narrow diff. For H arms, one `prange` loop computes the independent event-free intervals from the current arrays into scratch. It calls the unchanged 32-point scalar helper without fastmath. A separately compiled safe wrapper catches each cell's interval exception and writes a cell-local status. No native state, threshold, spike queue or aggregate diagnostic is written by the parallel loop.

The original serial cell scan then commits these results in ascending source index order. This retains threshold comparisons, spike append order, diagnostic reductions, refractory handling, direct-input writes, reset and CSR edge delivery order. A failed cell stops that scan at the same index as the original. Later cells may have been evaluated speculatively, but their results are discarded and their native state remains untouched. Failure telemetry counts committed source operations, rather than the extra speculative work. C0/C1 keep the signed source expression and do not invoke the parallel helper.

Scratch occupies 61 bytes per cell: seven float64 result fields, an int8 status and an int32 worker identifier. It is allocated once per `advance` call and reused each tick. The integer inversion count is temporarily stored in float64 and converted back exactly; the frozen helper caps it at 48. Unavailable cells receive status 2 and their unwritten scratch rows are never read. C arms allocate zero-length buffers. Each H tick adds a thread barrier, scratch traffic and a serial commit scan, so parallelization is not itself evidence of a speedup. No full-network performance forecast follows from this check.

The [synthetic plan](../validation/inhibitory-recurrent-parallel-plan.json) was written before its evaluations. A deterministic 128-cell graph has positive, negative and zero edges, eight input cells, all cells selected, and 300 ticks. Whole-run and uneven chunked executions compare every returned array's dtype, shape and bytes, every scalar/schema value, and complete checkpoints. Both H arms also match between one and four threads. Additional cases change an outgoing block after enqueue, exercise multiple invalid cells with an earlier partial spike, invalid unavailable state, deliberately corrupted infinite synthetic edge delivery, and a lower-bound failure. These artificial corruption fixtures test failure retention; they are not admissible graph conditions or physiological observations. Completed prefixes, partial states, pending queues, event order and continuation denial all match.

The detached helper check preserves all five native input arrays byte for byte, retains status and worker arrays, and observes worker IDs 0, 1, 2 and 3 with Numba's `workqueue` layer. The [compiler report](../validation/inhibitory-recurrent-parallel-compiler.txt) identifies the optimized `prange` loop. Raw evidence is in [the NPZ](../validation/inhibitory-recurrent-parallel-arrays.npz) and [array metadata](../validation/inhibitory-recurrent-parallel-arrays.json). The fixture checker can be inspected at [its source](../scripts/check_inhibitory_recurrent_parallel.py); its command is `.venv/bin/python scripts/check_inhibitory_recurrent_parallel.py`. It refuses to overwrite the retained plan or receipt.
