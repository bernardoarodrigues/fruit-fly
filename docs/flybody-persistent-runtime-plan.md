# Optional rolling-reference runtime: implementation and validation plan

This extends the reviewed standalone FlyBody inference task to the existing host bridge and full-neural runner. It changes finite reference bookkeeping only. The default FlyBody configuration remains the existing two-second bounded experiment; the default simulator remains NeuroMechFly. The source body, policy weights, actuator ordering/filters, physics and control clocks, command map and physical termination guards stay fixed.

## Explicit runtime boundary

Add `reference_mode: "bounded" | "rolling"` to FlyBody configuration. Bounded mode requires `horizon_s: 2.0`; rolling mode requires explicit `horizon_s: null`. Reject inconsistent pairs before graph/worker construction. A new optional `male-flybody-rolling-probe.json` selects rolling mode. Neither configuration is a natural-behavior claim.

Port the standalone `RollingWalkImitation` implementation without changing its algorithms. The rolling task retains exactly 66 pose/velocity rows: 65 are visible to the actor; the extra row supplies the post-step observable query. Every actor call refreshes this preview from only the current neural command and the continuously integrated target. Do not use future interventions, food coordinates or body recentering. Keep the original static observer trajectory markers and source model construction for physical-array parity; these markers are not an updated path prediction.

Worker changes are limited to task-factory selection, 65 versus 66 preview construction/installation, finite-horizon enforcement and truthful mode/provenance metadata. Both paths use the same policy/action/physics/diagnostic code. Rolling task source hashes join the worker metadata. Host and runner skip the duration preflight only when the declared horizon is null. Their clock, failed-step, transport, resource, close and explicit-reset behavior remains intact. The viewer labels rolling versus bounded reference operation from runtime metadata and preserves actual physical failures.

## Validation before a longer viewer

1. Check configuration rejection and finite versus unbounded horizon handling without allocating physics. Do not weaken the existing bounded lifecycle test.
2. Run the actual RPC host bridge over the frozen standalone 2 s bounded and rolling schedules. Compare every saved qpos/qvel/qacc/activation/control/action/target/native-clock sample, source model receipts and observations that exist in both records. Record differences in cached post-step reference tails separately; those tails are not actor inputs. Source/algorithm parity must precede full-graph runs.
3. Run the rolling bridge for the predeclared 12 s repeated stop/resume schedule, with current-only commands and unchanged physical guards. Verify actual 6,000-tick native state parity with the standalone rolling trace, clocks, bounded reference storage and host resource conservation. Check render/zero-step do not alter physics and reset restores the initial state. Retain any partial-state failure without tuning or automatic restart.
4. Freeze a separate full-graph experiment plan and implementation hashes before neural execution. Use actual physical odor/taste/club inputs, exact retained MaleCNS and unchanged Shiu parameters at 2 ms coupling. Include a 12 s locomotor calibration pair with/without sensory outgoing transmission and a separately labeled 12 s sensory-only trial. Preserve an identical first two seconds to the existing locomotor pair (mute 0.6–1.2 s); add mute intervals at 3.0–3.6 and 9.0–10.6 s in the longer pair. Do not require natural navigation, tune gains, or infer afferent equality after feedback diverges.
5. Journal actual inputs and ordered output spike arrays, not only event hashes, for independent review. Retain complete native state and stage-aware failure evidence. Use compact ignored raw artifacts and tracked hashes/summaries; protect frozen records against overwrite. Each run must record source revision, exact intervals, resource state, volatile physiology limits and raw artifact availability.
6. Inspect the actual rolling full-graph browser past the prior two-second boundary, then pause, change view and reset. Only describe extended viewer operation after these observations. Physical failure limits remain allowed to stop it; no finite experiment establishes indefinite stability.

## Interpretation limits

The standalone 12 s experiment covers a flat source floor and chosen straight-command schedules. It does not test arbitrary low-speed turns, obstacles, a male physical reconstruction, natural stance or sensory-guided foraging. The Shiu transfer's implausible negative voltages remain unresolved. The learned walking policy has idealized body feedback and a generated current-command preview; it is an explicit engineering surrogate below the connectome, not a reconstructed biological VNC controller. Wind receptors, compound-eye neural input, grooming and flight remain disabled in this backend until their own audited interfaces exist.
