# Independent review of panel archive publication

The [archive helper](../scripts/inhibitory_recurrent_panel_archive.py) has no identified source blocker for the panel's numeric data. An independent saved-file review passed **84/84 checks**, recorded in [this receipt](../validation/inhibitory-recurrent-panel-archive-independent-review.json). The producer separately reports 45/45 filesystem checks and 17 intentional exceptions. This review did not run the producer writer, loader or checker, and did not execute a neural model.

The reviewed module SHA256 is `3352c667249482e655116d073f899a3943e39c4d58fd53248801336abeade067`; the checker is `a4896139db56a132987ee61f90ff54f0a991d431c8cffffe0d78b7e3fb84b164`. The frozen [plan](../validation/inhibitory-recurrent-panel-archive-plan.json) is `a4594bfaf649bb205db6a0bbddc55f657d486379b1e2a93b935f8c2fcad9c4b5`, and the [producer receipt](../validation/inhibitory-recurrent-panel-archive-checks.json) is `0557d6e3880997a33be446c5bc6119c9a10bf8f51b0915d93e7d86c4e017f7ed`. All 37 retained artifact hashes and both source hashes were independently verified.

The source creates an exclusive publication lock, writes and fsyncs separate NPZ and typed-JSON temporary payloads, publishes them, checks their lengths/hashes, then publishes the completion marker last. Directory synchronization follows replacements. Readers reject leftover locks, temporaries or failure receipts and verify the completion transaction and both payload hashes before decoding. An exception preserves partial files and attempts to add a failure receipt; it does not turn an incomplete publication into a successful archive. Progress JSON replacement is explicitly opt-in. The retained spy trace shows the declared ordering and fsync calls; it is producer-instrumented evidence rather than a hardware durability experiment.

A separate decoder used NumPy only to load the saved NPZ and reconstructed its tree without importing the producer helper. It verified every array's dtype description, shape, item count, bytes and checksum. All expected fixture fields matched, including big-endian integers, noncontiguous logical values, packed structured arrays, zero-dimensional arrays, NumPy scalars, NaN/Inf values, negative zero, tuples and empty arrays. NumPy nonfinite values remain raw array/scalar bytes; ordinary Python nonfinite scalars have explicit tagged JSON representations.

Root and root-partial spike streams use exact 12-byte little-endian `(int64 tick, int32 index)` records. Their original integer dtypes, values and byte checksums were independently reconstructed. The writer checks ranges before packing, so larger input integer dtypes do not silently truncate. The loader verifies packed header semantics as well as outer checksums. The intentional count/endian corruptions remain in the saved fixtures with matching outer checksums, demonstrating why semantic checks are also necessary.

Saved payload/completion replacement failures retain locks, temporaries and failure receipts with no completion marker. The truncated temporary, competing lock, unrelated file, unsupported-object/structured-dtype and integer-overflow fixtures remain preserved. The checksum-corrupted fixture still disagrees with its completion record. No original producer evidence was edited during review.

The contract preserves dtype, shape and logical C-order bytes, not array strides or shared-memory aliasing. Object arrays, dtype metadata and padded/overlapping/aligned structured dtypes are rejected; the panel's plain numeric arrays and packed spike dtype fit the supported set. Cooperative lock users are protected; unrelated writers that ignore locks are outside the protocol. Mocked failures and local fsync calls cannot establish power-loss safety for every filesystem, and complete storage failure can prevent an additional diagnostic from being written. Those limits are appropriately stated. Numerical reference NaNs and valid negative-infinite ratio scores are supported without conversion to missing numeric data.
